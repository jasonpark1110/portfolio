# 바이너리 보안 플랫폼 MCP 서버 — 포트폴리오

> AI 에이전트가 바이너리 보안 스캐너를 직접 호출할 수 있도록 하는 Go 기반 MCP 서버

---

## 제품 개요

[Model Context Protocol (MCP)](https://modelcontextprotocol.io)을 구현한 Go 서버로, AI 에이전트(Claude 등)가 바이너리 분석 플랫폼과 직접 상호작용할 수 있도록 한다. 바이너리 업로드, 스캔 실행, SBOM 내보내기, 스캔 완료 대기 기능을 MCP 도구(tool)로 노출한다.

MCP는 AI 어시스턴트가 외부 서비스를 도구로 호출하기 위한 표준 프로토콜이다. 이 서버를 통해 보안 엔지니어는 자연어 프롬프트만으로 취약점 스캔 워크플로우를 자동화할 수 있다.

## 아키텍처

### 두 개의 바이너리, 하나의 모듈

```
부트스트랩 CLI    → 1회성 실행. 자격증명 입력 받아 플랫폼 API에서
                   토큰 발급 후 OS 데이터 디렉토리에 인증 파일 저장.

MCP 서버         → 장시간 실행 stdio 서버. 인증 파일 읽어
                   의존성 구성 후 MCP 서버 시작.
```

### 레이어 구조

```
진입점 (서버 / 부트스트랩 CLI)
    ↓
MCP 도구 레이어          도구 등록, 핸들러 래핑 (감사 로깅, 레이트 리미터)
    ↓
플랫폼 API 클라이언트     REST 클라이언트 (스캔, 내보내기, 바이너리, 토큰)
인증 레이어              토큰 파일 읽기/쓰기, 자동 갱신 세션
파일시스템 레이어         OS 경로, 즉석 ZIP 업로드, 원자적 파일 쓰기
설정 레이어              기본값 + 환경변수 오버라이드
로깅 레이어              구조화 로거 + 감사 로거
미들웨어 레이어           토큰 버킷 레이트 리미터
```

### 핵심 설계 결정

**DI 구조체로 의존성 관리**
모든 의존성을 단일 구조체로 조합해 시작 시 한 번 생성:
- 플랫폼 API 클라이언트 — 자동 토큰 갱신 세션으로 보호된 인증된 REST 클라이언트
- 내보내기 리소스 매니저 — 다운로드된 SBOM 파일을 TTL 기반 스윕이 있는 임시 MCP 리소스로 등록
- 스캔 대기 매니저 — 스캔 완료 대기 도구 전용 백그라운드 폴링 워커. 에이전트가 백엔드를 과부하시키지 않도록 스캔 상태 캐싱
- 감사 로거 — 모든 MCP 도구 호출을 구조화된 감사 항목으로 기록

**업로드 팬아웃**
여러 바이너리를 동시에 업로드할 때 `errgroup`으로 최대 10개 고루틴을 팬아웃. 개별 업로드 오류는 배치 중단 없이 결과별로 기록.

**토큰 자동 갱신**
뮤텍스로 갱신 호출을 보호. 다른 호출자가 이미 토큰을 갱신한 경우 중복 갱신 방지 (thundering herd 억제).

**내보내기 리소스 TTL 관리**
플랫폼에서 다운로드한 파일을 OS 전용 디렉토리에 저장하고 고유 ID로 MCP 리소스로 등록. 백그라운드 타이머가 만료된 파일 자동 정리.

**스캔 폴링 관리**
단일 백그라운드 고루틴이 추적 중인 모든 바이너리의 스캔 상태를 폴링. 각 바이너리별 다음 폴링 시각을 관리해 과도한 API 호출 방지. 타임아웃된 상태는 스캔 실패와 구분해 별도 상태로 마킹.

### MCP 도구 목록

| 도구 | 기능 |
|------|------|
| `upload_binary` | 바이너리 파일 플랫폼에 업로드 |
| `start_scan` | 업로드된 바이너리 스캔 시작 |
| `wait_for_scan` | 스캔 완료까지 폴링 대기 |
| `export_sbom` | SBOM/CBOM 다운로드 및 MCP 리소스 등록 |

모든 도구 핸들러에 감사 로깅과 레이트 리미터 사전 검사를 래핑.
