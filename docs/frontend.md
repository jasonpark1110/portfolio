# 바이너리 보안 플랫폼 — 프론트엔드 포트폴리오

> 보안팀을 위한 엔터프라이즈 바이너리 분석 SaaS의 React 프론트엔드

---

## 제품 개요

보안팀이 펌웨어·애플리케이션 바이너리를 업로드·스캔해 알려진 취약점(CVE/CNVD), 오픈소스 컴포넌트(SBOM), 라이선스 준수 여부, 보안 정책 위반을 탐지하는 엔터프라이즈 보안 SaaS.

- 대상 사용자: PSIRT 엔지니어, 보안 컴플라이언스 담당자
- 디자인 철학: Wiz/Snyk 스타일의 데이터 중심 UI — 마케팅 대시보드가 아닌 분석 도구
- 현재 버전: v5.0.452 (5개 메이저 버전에 걸친 장기 운영 제품)

---

## 기술 스택

| 영역 | 기술 |
|------|------|
| **프레임워크** | React 19, React Router v7 (hash-based) |
| **상태 관리** | MobX (UI 상태) + TanStack React Query (서버 상태) |
| **빌드** | Webpack 5 + SWC (Babel 대체) + esbuild 최소화 + PurgeCSS |
| **UI 프리미티브** | Radix UI (접근성), Semantic UI CSS (레거시 베이스) |
| **데이터 시각화** | Chart.js + chartjs-plugin-zoom |
| **가상화** | @tanstack/react-virtual |
| **국제화** | react-i18next (브라우저 언어 자동 감지) |
| **드래그앤드롭** | @hello-pangea/dnd |
| **내보내기** | jspdf (PDF), jszip, react-csv |
| **외부 연동** | Jira, Redmine |

## 아키텍처

### 이중 상태 관리 패턴

MobX와 React Query를 역할 분리해 공존시키는 구조:

```
MobX 스토어     → UI 상태, 네비게이션, 사용자 세션, 모달 상태
React Query     → API 데이터 페칭, 캐싱, 백그라운드 동기화, 페이지네이션
```

7개 도메인별 MobX 스토어를 단일 루트 스토어로 조합하고 Context API로 컴포넌트 트리에 주입. 스토어 값을 구독하는 컴포넌트는 `observer()` HOC로 래핑.

### 중앙 집중식 API 클라이언트

모든 HTTP 호출을 단일 진입점으로 집중:
- 도메인별 모듈 집계 (사용자, 리포트, 프로젝트, 이슈, 설정 등)
- 모든 요청에 브라우저 핑거프린트 헤더 자동 주입
- 401 응답 인터셉트 → 로그인 리다이렉트
- 환경변수 기반 백엔드 호스트 자동 전환 (개발/프로덕션)

### 라우트 아키텍처

3개 레이아웃 브랜치(비인증 / 메인 / 결과 상세)로 40개+ 페이지를 구조화. 결과 상세 뷰는 5개 분석 도메인(개요, 컴포넌트, 보안, 라이선스, 정책)의 깊은 중첩 라우트를 포함. 세션 검증 및 120분 토큰 갱신 주기를 갖춘 보호 라우트 구현.

### 커스텀 빌드 파이프라인

- **SWC**: Rust 기반 JS/JSX 트랜스파일러로 Babel 대체 — 빌드 속도 대폭 향상
- **esbuild**: 프로덕션 번들 최소화
- **PurgeCSS**: 빌드 타임에 미사용 CSS 제거 (번들 크기 감소)
- 컨텐츠 해시 기반 자산 파일명 → 캐시 무효화
- 개발 중 즉각 반영을 위한 HMR 구성

## 주요 기능

### 가상화 리스트
`@tanstack/react-virtual` 기반으로 수천 개의 CVE/컴포넌트 행을 DOM 부담 없이 렌더링. 보안·컴포넌트·라이선스 뷰 전반에서 적용.

### PDF 보고서 생성
jspdf 기반 컴플라이언스 보고서 생성. computed style을 제거한 인쇄 전처리 DOM 클론 파이프라인 설계.

### SBOM 내보내기/가져오기
CSV, ZIP 다중 포맷 내보내기 및 가져오기 검증 UI 구현.

### 외부 이슈 트래커 연동
Jira, Redmine 연동으로 CVE 발견 항목을 결과 뷰에서 직접 이슈로 생성.

### 자동 로그아웃
비활동 감지 훅으로 세션 만료 처리. 401 인터셉트 경로와 독립적으로 동작.

### 지식 베이스 (CVE 검색)
스캔 결과와 독립적으로 CVE 전체 텍스트 검색 가능한 별도 섹션.

## 디자인 시스템

CSS 변수 토큰으로 정의한 4단계 심각도 색상 체계:

```
Critical: #ff440c
High:     #ff7d00
Medium:   #ffae00
Low:      #ffde00
```

심각도는 색상·형태·레이블 3중 표현으로 색맹 접근성 확보. 컴포넌트 스코프 CSS를 JS 파일과 함께 배치. CSS-in-JS 미사용.

## 기여 내역

프론트엔드 전체를 단독 설계·구현.

- **아키텍처 설계**: MobX(UI 상태)와 TanStack React Query(서버 상태)를 역할 분리해 공존시키는 이중 상태 관리 패턴 도입. 7개 도메인 스토어를 루트 스토어로 조합하는 구조 설계
- **빌드 파이프라인 구축**: Webpack 5 + SWC + esbuild + PurgeCSS 조합으로 커스텀 빌드 시스템 구성. 미사용 CSS 제거로 번들 크기 감소
- **중앙 API 클라이언트**: 도메인별 모듈 분리, 핑거프린트 헤더 자동 주입, 401 인터셉트, 환경별 호스트 전환을 단일 진입점으로 구현
- **가상화 리스트**: `@tanstack/react-virtual` 기반 수천 행 렌더링. Security·Component·License 뷰 전반 적용
- **PDF 보고서 생성**: jspdf 기반 컴플라이언스 보고서 생성기. DOM 클론 후 computed style 제거하는 인쇄 전처리 파이프라인 설계
- **SBOM 내보내기/가져오기**: CSV, ZIP 다중 포맷 내보내기 및 가져오기 검증 UI 구현
- **외부 이슈 트래커 연동**: Jira, Redmine 연동 모듈 구현. CVE 항목을 결과 뷰에서 직접 이슈로 생성
- **디자인 시스템**: 4단계 심각도 색상 토큰 정의. 색상+형태+레이블 3중 표현으로 색맹 접근성 확보
- **세션 관리**: 120분 토큰 갱신 주기와 비활동 자동 로그아웃을 독립된 경로로 구현
- **국제화**: react-i18next 기반 다국어 지원. 전 화면 하드코딩 문자열 없이 i18n 처리
- **라우트 아키텍처**: 40개+ 페이지를 3개 레이아웃 브랜치로 구조화. 5개 분석 도메인의 중첩 라우트 설계
